## REDO — patching would leave a structurally wrong thing standing

### How the house decides who is in it (forge.js:6413 feeding `m.nodes` to familyTreeLayout)
You cannot patch the rails in. The house's membership is currently a side effect of whatever the wheel's mode happened to filter to, and every mode is single-type (mode.js:517), so the SCRIPTORIUM and the COURT are empty by construction forever. The house must resolve its own node set — family members from the whole vault, with the tier classifier pinned to the un-augmented wheel set so entering a house never re-sizes every god on the wheel. Any smaller fix (fake counts, chrome-only rails) reproduces the exact sold-vs-got gap that caused this escalation.

### The lineage 'bone' as a concept — today it is the generic engine wire with a brighter state
There is no arc renderer. webgpu.js:735 bows every wire toward world origin, which for a radial parent→child pair is ALONG the chord (measured median bow/chord 0.10), and webgpu.js:757 clamps idle, bone and fully-hot to the identical 2 framebuffer px at every zoom the house uses. So no amount of tuning house_bones can make a bone look like an arc — the width channel and the curvature channel are both dead before the dial reaches them. Needs a real per-instance lane (baked control point + bone width cap), not a brighter colour.

### The fan ring overflow guard (familytree.js:570-586, the two-attempt `P *= worst` nudge)
It is structurally incapable of converging: `dc = rad + fanDy` is affine in P, not proportional (fanDy is a constant offset from Rh), so a ratio nudge can never satisfy the constraint — instrumented, it fires and fails on all three worst families and then exits anyway at `if (worst >= 0.999 || attempt === 1) break;`. The span fix masks it. Replace with a direct cap computed before placement: `P = min(P, (Rh*0.94 - nodeR_max - fanDy) / radU_max)`, which needs no second pass at all.

### scripts/check-familytree.mjs
Adding a few families would leave a harness that structurally cannot see the bugs. It covers 3 of 36 families, one rank mode, one spread; its containment assertion ignores the node radius it just fetched; its rank assertion runs over the OUTPUT arc list, so an arc the layout deleted makes the check pass vacuously; and its span logic would alias a 376° ring to 352° via min/max. It printed ALL CHECKS PASS over four containment failures, a disk overlap, and two families whose cycle guard fires on every build. It needs to be a full sweep, not a spot check.

### boneIdx (forge.js:6392) — built from raw vault edge types before the layout runs
It counts a different population than the crown and always will: 39 Norse wires get lifted against a crown that says 20 LINEAGE ARCS, because 19 of them are consorts, aspects and cycle-broken arcs the tree never draws as lineage.
